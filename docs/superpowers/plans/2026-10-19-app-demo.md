# App de demo StreamDB (usuario + admin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Una página nueva en `/app` con aspecto de app de streaming, con entrada como usuario o admin, donde cada clic ejecuta un ejercicio (P1–P8) contra la API real y una columna lateral muestra qué hizo cada motor.

**Architecture:** Frontend estático sin build (HTML + CSS + módulos ES) en `src/demo/app/`, servido por Express en `/app`. Usa la API existente (`/api/v1/...`) con el encabezado `x-traza` y lee la traza de `/demo/api/trazas/:id`. Las pocas consultas que la app necesita y la API no tiene (cuentas para elegir, dispositivos, estado de los motores, licencias) van en un router nuevo `src/demo/app-rutas.js` montado en `/demo/api/app`.

**Tech Stack:** Node 24 + Express (existente), JavaScript del navegador sin frameworks, `node:test` + `fetch` para las rutas nuevas.

**Spec:** `docs/superpowers/specs/2026-10-19-app-demo-design.md`

## Global Constraints

- La app la sirve Express; nunca funciona como `file://`.
- No se modifica la lógica de `src/problemas/` ni el panel `/demo` (`src/demo/panel.html`).
- Cassandra sin `ALLOW FILTERING`: toda lectura nueva usa la partition key completa.
- Las consultas internas de la app (no las de los ejercicios) van envueltas en `sinTraza(...)` para no ensuciar la traza.
- Textos de la interfaz en español rioplatense, como el resto del proyecto.
- Colores por motor (los del boceto): Mongo `#4db33d`, Neo4j `#4c8eda`, Cassandra `#c9a0dc`, Redis `#e0453a`, PostgreSQL `#336791`.
- Series creadas desde la app: título con prefijo `Demo P1 · ` (el `PREFIJO_ALTA` existente), así "Reiniciar demo" las borra.
- Sin imágenes externas: carátulas = degradado derivado del id del contenido + título.

## Review Focus

1. **Falla "armada" que nadie consume:** si se arma una falla en un paso y la acción siguiente no tiene ese paso, la falla sigue armada y el aviso visible; solo se desarma al usarse o con "Desarmar". (Task 3, verificación manual en Task 3 y Task 7.)
2. **Tercer dispositivo sin lugar (409):** el player no debe quedar "reproduciendo"; muestra el mensaje y ofrece "Cerrar sesión en todos lados". (Task 5.)
3. **Sesión expirada mientras se "mira" (410 en progreso):** el player se detiene y avisa; no sigue mandando reportes. (Task 5.)
4. **Perfil Niños (+7) sobre "El faro del norte" (+16):** el destacado no puede ser contenido no apto; si P2 responde error, se muestra el mensaje, no un player vacío. (Task 4 y Task 5.)
5. **Un motor caído:** la pantalla de inicio lo marca rojo y las acciones que fallan muestran el error de la API en la columna lateral, sin romper la página. (Task 1 test, Task 3.)

### Task 3: Pedidos con traza y columna "Qué pasó con tu último clic"

**Files:**
- Create: `src/demo/app/js/api.js`, `src/demo/app/js/motores.js`
- Modify: `src/demo/app/index.html`, `src/demo/app/app.css`

**Interfaces:**
- Produces:
  - `api.js`: `export async function pedir({ metodo = 'GET', ruta, body, accion, pasos = [] }) → { status, cuerpo, traza }`. Siempre manda `x-traza: 1`; si hay una falla armada y su paso está en `pasos`, agrega `?fallarEn=<paso>` y la desarma. Después pide `/demo/api/trazas/<id>` y llama a `mostrarClic(accion, resultado)`. Nunca lanza por status ≥ 400: devuelve el resultado.
  - `api.js`: `export function armarFalla(paso: string|null)`, `export function fallaArmada(): string|null` (actualizan `#falla-armada`: "Falla armada: el próximo pedido falla en «paso» · Desarmar").
  - `api.js`: `export const leer = (ruta) => fetch(ruta).then(r => r.json())` para las consultas sin traza (`/demo/api/app/*`).
  - `motores.js`: `export function mostrarClic(accion: string, { status, cuerpo, traza })`. Pinta en `#motores`: título "Qué pasó con tu último clic: <accion>"; los cinco motores (encendido si tiene alguna op no `log`), cada uno con una frase y "×N operaciones"; detalle desplegable (`<details>`) con `op` y `detalle` de cada operación en orden; si `traza.saga`, los pasos con ✓ hecho / ✕ falló / ↺ compensado; si `status ≥ 400`, `cuerpo.error` en rojo.
  - `motores.js`: `export function frase(motor: string, ops: object[], cuerpo: object): string`.
- Frases (`frase`), por motor, la primera que aplique:
  - redis: `cuerpo.sesionReutilizada` → "Reutilizó la sesión de este dispositivo"; op `EVAL` y `cuerpo.idSesion` en un P2 → "Reservó un lugar en el cupo de pantallas"; `cuerpo.checkpoint` → "Guardó el segundo exacto (continuar viendo)"; solo lecturas → "Leyó sesiones / continuar viendo"; si no → "N operaciones".
  - cassandra: `INSERT`/`UPDATE`/`BATCH` → "Escribió en el historial"; `SELECT` → "Leyó el historial por perfil y mes".
  - neo4j: `MERGE` con `VIO` en el detalle → "Registró la señal VIO (para recomendar)"; `CREATE`/`MERGE` → "Creó nodos y relaciones"; `MATCH` → "Recorrió el grafo (vínculos, elenco, géneros)".
  - mongo: `find`/`aggregate` → "Leyó fichas y perfiles"; `update`/`insert` sobre `contenidos` → "Actualizó el catálogo"; ops `log` → se cuentan aparte como "log de la saga".
  - postgres: `UPDATE` → "Cambió el estado de licencias"; `SELECT` → "Consultó licencias vigentes".

### Task 5: Reproductor simulado (P2, P3, P4, P6)

**Files:**

- Modify: `src/demo/app/js/usuario.js`, `src/demo/app/app.css`

**Interfaces:**
- Consumes: `estado`, `pedir`, `mostrarClic`.
- Produces: `export async function abrirPlayer(idContenido: string, idEpisodio?: string)`; `export function cerrarPlayer()`.
- Valores fijos: `VELOCIDAD = 30` (1 s real = 30 s de episodio), un reporte de progreso cada `REPORTE_CADA_MS = 3000`.
- Comportamiento:
  - Abrir: `pedir({ metodo: 'POST', ruta: '/api/v1/reproducciones', body: { idPerfil, idDispositivo, idContenido, idEpisodio }, accion: '▶ Reproducir', pasos: ['reservar_cupo', 'registrar_inicio'] })`. Con 201 guarda `estado.sesion = { idSesion, idContenido, idEpisodio, posicionSeg, duracionSeg }` y muestra el player a pantalla completa (título, episodio, barra, tiempo, ⏸, "Saltar al final", ✕). Duración: de `continuar-viendo` o, si no está, de la ficha vía `GET /api/v1/contenidos/:id/trazabilidad` (sin mostrar en la columna), y 2700 s por defecto.
  - Con **409** (sin lugar): no abre el player; muestra "Ya hay N pantallas en uso en esta cuenta" con botones "Cerrar sesión en todos lados" (`POST /api/v1/cuentas/:id/cerrar-sesiones`, `accion: 'Cerrar sesión en todos lados'`) y "Elegir otro dispositivo" (Review Focus 2). Con otro error: el mensaje de la API.
  - Cada 3 s: `POST /api/v1/reproducciones/:idSesion/progreso` con `{ posicionSeg }` (`accion: 'Mirando… reporte de progreso'`). ⏸ manda `evento: 'pausa'` y detiene el reloj; ✕ manda `evento: 'cierre'` y después `DELETE /api/v1/reproducciones/:idSesion`.
  - Con **410** en un reporte: se detiene el reloj y se muestra "La sesión expiró: hace más de 2 minutos que no se reportaba" (Review Focus 3).
  - Al llegar a `duracionSeg` o con "Saltar al final": `POST /api/v1/reproducciones/:idSesion/fin` (`accion: 'Terminó el episodio'`, `pasos: ['marcar_finalizado', 'continuar_viendo', 'senal_vio']`). Si `cuerpo.siguiente`, ofrece "Siguiente episodio ▶" (nuevo `abrirPlayer` con ese episodio). Al cerrar el player, `#/home` se vuelve a pintar.
